# Civic Tracker

A mobile-first web app and Android app for reporting and tracking civic infrastructure problems such as potholes, water outages and broken streetlights. Citizens report issues on a map, the community votes and verifies fixes, and NGOs and admins manage resolution.

**Stack:** Next.js 14 (App Router), TypeScript, Tailwind CSS, Prisma 7, PostgreSQL, NextAuth v5, Mapbox GL, Web Push, and an optional local vision model (Ollama with LLaVA) for image moderation. The mobile app uses Expo and React Native.

## Features

- Map of reported issues with a multi-step report form and photo upload
- Votes, comments, abuse flags and community verification of fixes
- Trust scores, badges and a contributor leaderboard
- NGO registration with admin approval, and a daily deadline-check cron job
- Admin dashboard for issues, flagged content, users, NGOs and settings
- Web push and Expo push notifications
- Optional AI analysis: duplicate detection, priority scoring and image moderation

## Quick start

You need Node.js 20 or newer and either Docker or a PostgreSQL 14+ server. Ollama is optional.

```bash
git clone https://github.com/shreyas-078/civic-tracker.git
cd civic-tracker
docker compose up -d      # starts PostgreSQL (skip if you use your own server)
npm run setup             # installs packages, writes .env.local, runs migrations
npm run dev
```

Open http://localhost:3000.

`npm run setup` never installs system software and never asks for administrator rights. It does the following:

1. Checks the Node version and runs `npm install`.
2. Creates `.env.local` from `.env.example`.
3. Generates `NEXTAUTH_SECRET`, `CRON_SECRET` and the web push (VAPID) keys.
4. Runs `prisma generate` and `prisma migrate deploy` against `DATABASE_URL`. The default matches the Docker database.
5. Lists the settings you still have to fill in.

Options: `npm run setup -- --seed` also loads demo data, and `npm run setup -- --skip-db` skips the database steps. If the database is not reachable, the script says so and tells you what to run. Run it again once the database is up.

## Configuration

Edit `.env.local`. Google sign-in and the map need keys that only you can create.

| Variable | Required | Purpose |
|---|---|---|
| `DATABASE_URL` | yes | PostgreSQL connection string. The default matches `docker-compose.yml`. |
| `NEXTAUTH_URL` | yes | Public URL of the app, `http://localhost:3000` locally. |
| `NEXTAUTH_SECRET` | yes | Session secret. Generated by setup. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | for Google sign-in | See below. |
| `NEXT_PUBLIC_MAPBOX_TOKEN` | for the map | Public token from account.mapbox.com. |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | for web push | Generated by setup. The two public values must match. |
| `CRON_SECRET` | production | Protects the cron endpoint. Generated by setup. |
| `OLLAMA_BASE_URL`, `OLLAMA_MODEL` | optional | Local vision model. Defaults are `http://localhost:11434` and `llava`. |
| `IMAGE_MODERATION_ENABLED` | optional | Set to `false` to turn image moderation off. |
| `ENABLE_DEMO_LOGIN`, `NEXT_PUBLIC_ENABLE_DEMO_LOGIN` | optional | Demo logins, local development only. Both default to `false`. |

**Google sign-in:** in the [Google Cloud Console](https://console.cloud.google.com), create an OAuth client of type Web application. Add `http://localhost:3000` as an authorised origin and `http://localhost:3000/api/auth/callback/google` as a redirect URI. Copy the client ID and secret into `.env.local`.

**AI features (optional):** install [Ollama](https://ollama.com/download), then run `ollama pull llava` and `ollama serve`. The app works without it and falls back to default values for analysis.

## Accounts and admin access

- **Demo logins are off by default.** To try the app without Google sign-in, set `ENABLE_DEMO_LOGIN="true"` and `NEXT_PUBLIC_ENABLE_DEMO_LOGIN="true"` in `.env.local` and restart. This adds quick sign-in buttons for `demo@civictrack.local` (password `demo`), `admin@civictrack.local` (`admin`) and `ngo@civictrack.local` (`ngo`). Never enable it on a public deployment, because anyone could sign in as an admin.
- **Seed data:** `npm run prisma:seed` creates `admin@civictrack.dev`, `ngo@example.com` and `citizen@example.com`, all with the password `password123`, plus sample issues. Development only.
- **Make a user an admin:** sign in once, then run
  ```sql
  UPDATE users SET role = 'ADMIN' WHERE email = 'you@example.com';
  ```
  or edit the user in `npm run prisma:studio`. The admin panel is at `/admin`.

## Mobile app (Expo)

The Android app lives in `mobile/`. It needs a development build, because Expo Go does not support its native modules.

1. Install [Android Studio](https://developer.android.com/studio) with the Android SDK and set `ANDROID_HOME`.
2. Create a Firebase project, add an Android app with the package name `com.civictrack.app`, and save its `google-services.json` as `mobile/google-services.json`. The file is not in the repository.
3. In `mobile/app.json`, change `owner` and `extra.eas.projectId` to your own Expo account and project. Run `eas init` in `mobile/` to create the project ID.
4. In `mobile/constants/theme.ts`, set `API_BASE_URL` to your computer's LAN address, for example `http://192.168.1.20:3000`. The phone and the computer must be on the same network.
5. Build and run:
   ```bash
   cd mobile
   npm install
   npx expo prebuild
   npx expo run:android
   npx expo start --dev-client
   ```

For Android push notifications, upload a Firebase service-account key to EAS with `eas credentials`, or run `node upload-fcm-key.mjs <key.json>` from `mobile/`. Keep that key out of the repository.

## Deployment

The web app runs on Vercel or any Node host.

1. Provision PostgreSQL and run `DATABASE_URL="..." npx prisma migrate deploy`.
2. Set every variable from the table above in your host's environment settings. Set `NEXTAUTH_URL` to your public URL and add it to the Google OAuth origins and redirect URIs.
3. `vercel.json` schedules `/api/cron/deadline-check` daily at 09:00 UTC. It needs `CRON_SECRET`.

**Known limitation:** uploads are written to `public/uploads` on the local disk. Most hosts, including Vercel, do not keep files across deployments, so use object storage before relying on uploads in production.

## Troubleshooting

- **Cannot connect to the database (P1001):** check that `docker compose ps` shows the database as healthy, or that your server is running and `DATABASE_URL` is correct.
- **`relation ... does not exist`:** run `npx prisma migrate deploy`.
- **Map is blank:** `NEXT_PUBLIC_MAPBOX_TOKEN` is missing. Restart `npm run dev` after editing `.env.local`.
- **Mobile "Network request failed":** `API_BASE_URL` points to `localhost`, which on a phone means the phone itself. Use your computer's LAN address.
- **Mobile build fails on `google-services.json`:** the file must exist at `mobile/google-services.json`.
